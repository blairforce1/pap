# Spec review: pm-mode

Reviewed 2026-11-10 against spec.md at draft; dispositions by @blairforce1.

## 1. Executive verdict

**Pass with conditions.** No Blocker and no perspective failed. 30 Majors as returned, 25 after folding. Most sit in five themes: the guard can stop binding the PM without any signal showing it, two of the Operations signals cannot be computed from the logs as specified, the launch checks are not said to be a script, several refusals name a route that cannot clear the block, and the edges of the mode (solo outside a repository, a machine without the plugin, a resume) are undefined.

Class: feature. Mandatory set: none (no class matrix in `product/`; the process's starting set names none for feature). Run by content: the default six, plus ux (the owner drives a command and a session), gdpr (the spec does not state that no personal data is held) and ai-act (the change starts and steers a Claude Code session; EU exposure unknown). Skipped: soc2 and iso27001, neither scope applies.

## 2. Top findings

1. **SEC-001** (Major; reliability, operations reinforce): a Claude Code release that puts an agent id on main-session calls unbinds the PM silently, and zero refusals reads as healthy.
2. **SEC-002** (Major): files outside every adopting repository are not judged, so the PM can edit Claude Code's settings, the plugin's hooks and the logs the signals read.
3. **OPS-001** (Major; reliability reinforces): the refusal log has no session id or caller, so two health signals cannot be computed.
4. **QA-001** (Major): the launch refusals are called enforcement and are never said to be a script.
5. **SEC-004** (Major; qa reinforces): only `git commit` is checked; other commit-creating commands are neither judged nor listed as limits.
6. **QA-003** (Major; reliability, security reinforce): a path that does not exist yet cannot be resolved, and the failure direction is not stated.
7. **REL-004** (Major; cost reinforces): a dead or orphaned cycle stays in flight for ever; the launch's step order is unspecified.
8. **UX-002** and **OPS-005** (Major): a commit blocked by a stray file names routes that cannot clear it, and nothing stops a destructive clean-up.
9. **OPS-004** (Major): the per-session undo, `--solo`, appears to remove the launch path.
10. **QA-010** (Major): on a machine without the plugin the welcome session has the mode and neither role nor guard.

## 4. Cross-cutting themes

- **A control that fails silently.** Security, reliability and operations each found that the PM can become unbound, or the guard switched off, with every band still reading good. The spec has no positive signal that the guard is active.
- **Signals the model writes.** The `yes`, the `message` and `report` lines, and In flight are all appended by the party they measure (SEC-006, OPS-003, REL-004, REL-007).
- **A script or a skill.** What `/pap:pm` enforces, and what stops a sub-agent invoking it, depend on a mechanism the spec does not name (QA-001, QA-002, OPS-004).
- **The commit check.** It is the honest boundary for shell writes, and it is unbounded in time (PERF-001), incomplete in commands (SEC-004), misleading in its message (UX-002) and dangerous in its obvious remedy (OPS-005).
- **One tracker, many sessions.** Concurrency, keying and a hung push (REL-003, REL-008, REL-006).

## 5. Trade-off register

| Conflict                                         | Options                                                                                                              | Consequence                                                                                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Security against the H-003 lesson (SEC-003)      | Restrict the sub-agent types the PM may spawn; tie a writing sub-agent to a logged launch; leave delegation unbound. | A type list alone does not close it; tying to a launch closes it at the cost of more machinery; unbound leaves the measure as the catch. |
| Security against a usable session (SEC-002)      | Judge everything outside a repository; judge named directories only.                                                 | The first refuses memory and scratch writes; the second leaves anything unnamed open.                                                    |

## 6. Gaps and questions

- No threat model names the attackers: the PM model itself, and injection arriving through cycles, briefs or the web.
- No load basis: tool calls a session and a cycle, cycles in parallel, so the guard's total overhead is never sized.
- No mode indicator the owner can see mid-session, and no `pap claude --help` text for `--solo`.
- No failure behaviour for the session-start hook itself: a slow, missing or corrupt tracker.
- What happens to cycles in flight when the guard is reverted (Undo step 2).
- Is withdrawing 0025 by revert itself an intervention needing a record under INV-008?
- Where do `/intent` and `/spec` commit in a PM session, the main checkout or a change work tree?
- How does `pap doctor` show that a session was started by `pap claude`, run outside its environment (First check 4)?
- When a companion push fails, is the next commit's push a catch-up?
- Can briefs or `message` events quote third parties? Is pap ever run for an employer or client?
- No lawful basis or retention period is noted for the tracker and logs.

## 7. Recommended conditions for approval

Every Major above. In short: a live check and a positive signal that the guard binds the PM (SEC-001); the guard's own files and logs out of the PM's reach (SEC-002); the commit-creating commands judged or listed (SEC-004); path resolution and its failure direction stated (QA-003); the logs given the fields the signals need (OPS-001); a deterministic or cross-checked count of messaged cycles (OPS-003); the launch checks named as a script, and the mechanism that stops a sub-agent (QA-001, QA-002); one actor for a launch (UX-004); a single-writer rule for the tracker (REL-003); a way to clear a dead cycle and a stated launch order (REL-004); a bound on cycles in flight or a stated reason for none (COST-001); refusals that name a remedy that works and forbid the destructive one (UX-002, UX-003, OPS-005, UX-005); the mode's edges defined (QA-009, QA-010, UX-001, OPS-004, QA-005); the guard's cost bounded on the commit path and near zero for sub-agents (PERF-001, PERF-002); the missing events defined (QA-006).
