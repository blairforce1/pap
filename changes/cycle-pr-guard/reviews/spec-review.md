## 2. Top findings

1. **SEC-001, QA-001 (Major):** `git checkout change/x --` is a branch switch, and rule 27.2 lets through any checkout with `--`. The refusal text advertises the form.
2. **REL-001, SEC-003, QA-002 (Major; OPS-006):** nothing says what happens when git cannot place the directory: one the same command creates, a variable, `pushd`. Today that is skipped silently, so both rules are unapplied.
3. **SEC-002 (Major; QA-012):** rule 27.1 follows the directory, so `gh pr create -R` from outside the repository is unbound; `gh api` on `pulls` is neither covered nor named a limit.
4. **REL-002, QA-004 (Major; OPS-004, SEC-011):** `pap doctor` hardcodes `main` and reports drift in every repository, which breaks the adoption guides' own "doctor exits 0" step.
5. **OPS-001 (Major; SEC-006):** the log line carries no command, so "false refusals" and "saves" cannot be read from it.
6. **OPS-002, QA-007 (Major):** `pap doctor` leaves no record that it ran, so the second measure rests on recall.
7. **OPS-003 (Major):** rollout to the other two repositories, on which the measure depends, is not described.
8. **QA-005 (Major):** decision 0027's revisit is not in one of decision 0010's typed forms, so `pap revisits` cannot read it.
9. **QA-006 (Major):** the baseline counts "lacked a label" and the measure counts "first run failed"; a label added a second after opening may fail the first run with the guard working.
10. **QA-003 (Major):** a literal class label beside an unreadable label value has two readings.

## 4. Cross-cutting themes

- **Fail direction is decided case by case.** A label that cannot be read fails closed; a directory that cannot be placed, a parse failure, a missing `jq` and a hung git are open or unstated.
- **The signals cannot be read as written.** The log has no command, the doctor leaves no record, the first measure and its baseline count different things.
- **`main` and "adopting" are assumed.** The doctor item and the adoption guides disagree.
- **The rule's edges are plain commands.** A trailing `--`, `-R`, `gh api`, `branch -m`: none needs `bash -c`.

## 5. Trade-off register

- **Refuse what cannot be placed, or let it through (REL-001).** Closed is consistent with the label rule and costs a split command; open keeps compound commands working and leaves the incident's likeliest one-liner unguarded.
- **A recorded reading against the intent's `pap doctor` (OPS-002).** A line at session start makes the second measure readable and adds to the hook; the doctor alone keeps the scope and leaves the measure to recall.
- **Drift in a repository mid-adoption (QA-004).** Drift is true there and breaks the guides; `skipped` keeps the guides and hides the state.

## 6. Gaps and questions

- Who the guard is for: an agent that drifts, not one that is steered. Decision 0027 should say so.
- Whether a cycle is always a sub-agent of the PM session's process, so the mode reaches the hook.
- Version skew between the plugin and the pinned `pap` during rollout.
- Submodules, and a bare repository with only linked work trees.
- Whether `pr-checks` reads labels from the event or live.
- Whether adopting repositories always have the seven `class:*` labels.

1. Rule 27.2's allowed forms listed exactly; a trailing `--` is a switch (SEC-001, QA-008).
