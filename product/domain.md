# Domain: PAP

The words every spec and scenario uses. A term is defined once; a state and an event belong to a term. Added by the spec that first needed it, in the same diff (decision 0017).

## Terms

- **Owner**: the human who owns a repository and its GitHub account or administers its organisation; the only party who runs `pap new`. Ready to create `<name>`: at their own terminal, with a sufficient owner sign-in, a registered agent app with an all-repositories installation on the owner, a plan that gives the repository a main ruleset, and nothing named `<name>` in the current directory or for the owner on GitHub. (spec: pap-new)
- **Owner sign-in**: the owner's own `gh` sign-in, in the owner's gh directory (gh's default one, never the agent's). States: signed out, lacks a scope (`repo` or `workflow`), reports no scopes (a fine-grained token), sufficient. (spec: pap-new)
- **Agent**: a Claude Code session acting on GitHub as the agent app, never as the owner (decision 0023). (spec: pap-new)
- **Agent shell**: a shell in which `gh` and `git` act as the agent. Known by any one of three signals: the session marker Claude Code sets, the agent's gh directory in use, or the agent's `gh` first on the path. (spec: pap-new)
- **Agent app**: the `pap-agent` GitHub App and its key on this machine. States: unregistered, registered. (spec: pap-new)
- **Agent installation**: the agent app installed on an owner. States: none, all-repositories, selected-repositories. It covers a repository or does not. (spec: pap-new)
- **Agent token**: a short-lived token of the agent installation, scoped to one repository. States: not minted, minted. (spec: pap-new)
- **Layer**: a named part of the template: base, dotnet, go, risk. (spec: pap-new)
- **Greenfield repository**: a GitHub repository and its clone that `pap new` made from nothing. It is this command's own when the first commit on `main` is the first commit as defined below, and the clone's first commit, where a clone exists, is the same commit; later commits on `main` do not change that. States, in order: absent, committed (the first commit exists in the clone only), created (the repository exists on GitHub, empty), pushed, set up, settings applied, welcomed. (spec: pap-new)
- **Recorded**: written in the repository's `.config/pap.toml`: the applied template version and the layers (INV-011). (spec: pap-new)
- **Run**: one invocation of `pap new` for one name and owner. States: in preflight, creating, stopped (at a named step), complete. (spec: pap-new)
- **Step**: one of the six parts of creation, in order: first commit, repository creation, first push, clone setup, repository settings, agent token. The first three are made once and never again; the last three are convergent, checked on every run and redone only where they are not as they should be. (spec: pap-new)
- **Preflight**: the checks a run makes before it creates anything: the name, the owner, the layers and the visibility, the shell and its terminal, the owner sign-in, the agent app and the agent installation, what the owner's plan and organisation allow, and what already exists of that name. It ends with the summary. (spec: pap-new)
- **Summary**: what preflight shows last and the owner confirms: the login acted as, the owner and name, the visibility, the layers, and the author name and email of the first commit. (spec: pap-new)
- **Prompted step**: something the run asks the owner to do and waits for or names in advance: the sign-in, a scope refresh, confirming the summary, adding a repository to the agent installation, a setting only the owner can change. Not a hand-run step. (spec: pap-new)
- **First commit**: the one commit that starts `main`: the template at the recorded version and layers, and a README whose only line is `# <name>`. The README belongs to no layer. (spec: pap-new)
- **Clone setup**: installing the pinned tools and the git hooks in a clone. It writes no tracked file. (spec: pap-new)
- **Clean**: of a working tree, no change to a tracked file and no untracked file that is not ignored; of `pap doctor` and `pap repo status`, exit 0 with no item `missing` or `drift`. (spec: pap-new)
- **Repository settings**: the GitHub side that `pap repo apply` writes: settings, the main ruleset, labels. States: not applied, applied. (spec: pap-new)
- **Main ruleset**: the ruleset on `main` in the repository settings. A bypass actor is anyone it lets past. (spec: pap-new)
- **Welcome session**: the agent session a run starts last, in the clone. It is given what the run did, where the owner is and what is installed, and is told to ask what the owner wants and start nothing. A PM session where the pap plugin is installed (spec: pm-mode). (spec: pap-new)
- **Installed**: of a skill, mod or agent, present for Claude Code on this machine from a plugin of pap's marketplace. (spec: pap-new)
- **Install prompt**: the one-line prompt in pap's docs that has Claude install pap at an exact version. (spec: pap-new)
- **Release**: a tagged version of pap, cut by `scripts/release.sh`. (spec: pap-new)
- **Work tree**: a checkout of an adopting repository on one branch. It holds changes that are staged, unstaged, or untracked and not ignored. (spec: pm-mode)
- **Adopting repository**: a repository that adopts PAP, known by an executable `scripts/guard-branch.sh` at its root; each of its work trees counts. pap is one. (spec: pm-mode)
- **Product layer**: the files under `product/` of an adopting repository. States: absent (no `product/vision.md`), present. (spec: pm-mode)
- **Session**: one Claude Code session started by `pap claude`, and so an agent. Its mode is set when it starts and does not change while it runs: solo (started with `--solo`, anywhere), PM (in an adopting repository, with the pap plugin installed), or none (outside every adopting repository, or without the plugin). A mode belongs to a start: a resumed conversation takes the mode of the start that resumed it. A session started without `pap claude` has no mode. (spec: pm-mode)
- **PM session**: a session in PM mode: the main session of the project manager of decision 0018, in an adopting repository. It is the session itself, never a sub-agent of it. (spec: pm-mode)
- **Solo session**: a session the owner started with `pap claude --solo`; bound as a session was before pm-mode, and not by the PM paths. (spec: pm-mode)
- **Sub-agent**: an agent a session spawns, of a named type (`pap:cycle`, `pap:cycle-mechanical`, `pap:reviewer`, or any other). (spec: pm-mode)
- **Role**: the text a PM session is given when it starts: that it is the project manager, the routes and when to propose each, the PM paths, what it never does (rule 18.1), and where the tracker stands. (spec: pm-mode)
- **Ask**: what the owner says they want of a PM session. States: a question (answered, nothing launched), unripe (not yet clear what is wanted), ripe (clear, and a route covers it), with no route. (spec: pm-mode)
- **Route**: how an ask is carried: `/envision`, `/intent` (then `/spec`) in the PM session, or a cycle running `/change`. Rule 20.2 decides between `/intent` and a cycle. (spec: pm-mode)
- **Slug**: a change's id, as a change branch allows after `change/`: a letter or digit, then letters, digits, `.`, `_` or `-`. (spec: pm-mode)
- **PM paths**: the only paths a PM session writes, and in its own adopting repository only: any file under `changes/<slug>/`, a file `features/<slug>.feature` directly under `features/`, and `product/**`; and, wherever it lives, the tracker. A path is judged where it resolves, a path that does not exist yet from its deepest existing parent. (spec: pm-mode)
- **Guard's own files**: Claude Code's settings files, the directory an installed plugin runs from, and pap's state directory apart from the tracker. In no adopting repository, and refused to a PM session all the same. (spec: pm-mode)
- **Write**: a change to a file by the Edit, Write or NotebookEdit tool, or a commit. A file changed by a shell command is a write only when it is committed. (spec: pm-mode)
- **Guard**: the check that runs before an agent's tool call and refuses it or lets it through. A refusal blocks the call and names the rule and what to do instead. States, for a PM session: binding, or not binding (the main session's own calls carry an agent id, so it cannot be told from a sub-agent). (spec: pm-mode)
- **Refusal log**: a file on the machine, outside every repository, with one line per write refused as outside the PM paths: the time, the session, the mode, the caller (the main session, or a sub-agent's id and type), the path and the repository; and one line, of its own kind, per tool call the guard could not read. (spec: pm-mode)
- **Message log**: a file beside the refusal log with one line for each message a PM session sends a sub-agent and for each sub-agent stop, written by the guard. (spec: pm-mode)
- **Launch record**: a line, among the guard's own files, for each `/pap:pm launch <slug>` the owner typed; the yes of rule 18.2. A launch the PM session invokes itself leaves none. (spec: pm-mode)
- **Session log**: a file beside the refusal log with one line per session `pap claude` starts: the time, the mode, the repository and the Claude Code version; one line each time the role is given, naming whether at a start, a resume, a `/clear` or a compaction; and one line when a start finds the guard not binding. (spec: pm-mode)
- **Tracker**: a PM session's state file, event log and briefs for one adopting repository, in a git repository of their own outside it: on the machine by default, or in a clone of a companion repository the owner pointed it at. Keyed by the repository's owner and name, or by its root path when it has no `origin`. States: absent, started; once started, clean or uncommitted, and held by one PM session or by none. (spec: pm-mode)
- **State file**: the tracker's short, rewritten file: what is in flight, what waits on the owner, what is next. In flight is rewritten from the event log, never by hand. (spec: pm-mode)
- **Event log**: the tracker's append-only file, one line an event: the time, the event, the slug and a line of text. Events: start, restate, yes, launch, report, message, pause, resume, merge, decision. (spec: pm-mode)
- **Brief**: the one file a cycle is given. Its first line names its route, its second the item of rule 20.2 that decided it, and it carries a budget in tokens or wall time. Complete when it has all three. (spec: pm-mode)
- **Cycle**: one change run by one sub-agent a PM session launched from one brief: one work tree, one draft pull request, one report (decision 0018). States: launched, reported, paused, merged, abandoned. In flight: launched, with no later `report`, `pause` or `merge` event and no `decision` event starting `abandoned`. Mechanical as decision 0024 defines it, or not. (spec: pm-mode)
- **Companion repository**: a private repository of the owner's that holds a project's tracker. Its remote accepts pushes or rejects them. (spec: pm-mode)
- **Change**: one increment of work, known by its slug, with a class set by its intent. It needs a plan when its class is feature, infra or security-sensitive, its change branch carries an accepted intent and spec, and it did not start unplanned. It started unplanned when its change branch carries code and no plan at all, a draft included. (spec: plan-step)
- **Change branch**: the branch `change/<slug>` of a change, as this clone holds it. It carries the change's intent, spec, plan and code, in that order. (spec: plan-step)
- **Accepted**: of an intent, a spec or a plan: its file, as committed at the tip of the change branch, names who said yes and when, both filled. A draft is the same file without them, or with them only in the work tree. States, for each: absent, a draft, accepted. A plan is accepted only while its spec has no commit later than the one that accepted the plan; after one it is a draft. (spec: plan-step)
- **Code**: a commit on a change branch that changes a path outside `changes/`, `features/` and `product/` (rule 21.1's line). (spec: plan-step)
- **Plan**: `changes/<slug>/plan.md`: how an accepted spec will be built, in at most 1000 words by `wc -w` over the file, less the values of `accepted-by`, `accepted-on` and `reviewed-by`, in the sections Increments, Design, Fit, Tests and Observation. States: absent, a draft (a plan draft), accepted. A plan draft is reviewed when its plan review register exists; reviewed is not a state. (spec: plan-step)
- **Increment**: one part of a plan that can be built, tested and committed on its own, naming the scenarios of the spec it satisfies. (spec: plan-step)
- **Planner**: the sub-agent of type `pap:planner` that drafts a plan from the accepted spec and the repository, and answers its review once. It reads and returns; it writes nothing. It fails when it ends without a report, returns one missing the header or a section, or reaches a cap. (spec: plan-step)
- **Plan review**: the reading of a plan draft by a sub-agent of type `pap:plan-reviewer` that did not draft it, from three viewpoints: conformance (to the spec), design (fit with the repository as it is, and instructions embedded in the plan) and verification (tests and evidence); a security-sensitive plan adds security. It fails as a planner does. (spec: plan-step)
- **Plan review register**: `changes/<slug>/reviews/plan-review.md`: first the planner's and the plan reviewer's tokens and minutes and the time the owner was told the plan was ready, then one line a finding, with its viewpoint, its severity and its disposition. A finding is fixed (by the planner), or has the owner's disposition (accepted, rejected with a reason, deferred to a phase), or waits. A finding marked `return: spec` is never fixed, and is accepted or rejected only. (spec: plan-step)
- **Build**: a cycle whose brief's route is `/change`. (spec: plan-step)
- **Deviation**: a place where a build did not do what its accepted plan said: an increment split, merged, dropped or added, a design it replaced, or a part of the plan it did not act on. (spec: plan-step)
- **Turn**: what a session does between one message of the owner's and the next. An answer the owner gives to a question the session puts inside a turn does not end it. (spec: spec-board-keeps-tools)
- **Perspective**: one viewpoint of the spec-review plugin (security, reliability, operations, cost, performance, qa, ux, gdpr, ai-act, soc2, iso27001), a skill of its own that a person can also invoke directly; the board is the skill that runs those a spec needs and consolidates them. (spec: spec-board-keeps-tools)
- **Spec review**: the reading of a spec draft that `/spec` runs: the perspectives the change's class requires, each read by a sub-agent of its own. States: running (a perspective has not reported), returned (every perspective has reported, or the owner has said to go on without one that failed). A perspective fails when its sub-agent ends without a verdict and a findings table, or has not reported 20 minutes after it started. (spec: spec-board-keeps-tools)
- **Spec review register**: `changes/<slug>/reviews/spec-review.md`: the report of a spec review as it returned (one perspective's report unchanged, or the board's consolidated report of several), one line a finding, each with a disposition that is empty until the owner gives it (accepted, rejected with a reason, deferred to a phase). States: absent, written. (spec: spec-board-keeps-tools)

## Events

- **The owner runs pap new**: starts a run, in preflight. (spec: pap-new)
- **The owner confirms the summary**: moves the run from in preflight to creating. Declining it stops the run. (spec: pap-new)
- **The first commit is made**: moves the greenfield repository from absent to committed. It appears whole or not at all. (spec: pap-new)
- **The repository is created**: moves it from committed to created. (spec: pap-new)
- **First push**: the first commit is pushed to `main`, moving the greenfield repository from created to pushed. The one direct push to `main` in its history. (spec: pap-new)
- **The clone is set up**: moves it from pushed to set up. (spec: pap-new)
- **The repository settings are applied**: moves the greenfield repository from set up to settings applied; the main ruleset exists from here. (spec: pap-new)
- **An agent token is requested**: the run asks the agent installation for a token for the repository. (spec: pap-new)
- **An agent token is minted**: moves the agent token from not minted to minted. (spec: pap-new)
- **The welcome session starts**: moves the greenfield repository to welcomed and the run to complete. (spec: pap-new)
- **The run stops**: moves the run to stopped at a named step; nothing is undone. (spec: pap-new)
- **A release is cut**: `scripts/release.sh <version>` is run; it creates the release or refuses. (spec: pap-new)
- **The owner runs pap claude**: starts a session; in an adopting repository a PM session, with `--solo` a solo session. (spec: pm-mode)
- **A PM session starts**: at `pap claude`, on a resume, after a `/clear` and after a compaction; each time it is given the role. (spec: pm-mode)
- **The PM session writes**: a write by the PM session itself; made when it is within the PM paths or in no adopting repository, refused otherwise. (spec: pm-mode)
- **The PM session commits**: a write; `git commit` run by the PM session in a work tree, judged on every change that work tree holds. (spec: pm-mode)
- **A sub-agent commits**: `git commit` run by a sub-agent; the PM paths do not bear on it. (spec: pm-mode)
- **A caller runs a command**: a shell command run by a PM session, a solo session or a sub-agent, judged by the guard as before pm-mode. (spec: pm-mode)
- **pap claude --solo is run**: by the owner at their own terminal, which starts a solo session, or from an agent shell, which is refused. (spec: pm-mode)
- **A sub-agent runs the /pap:pm script**: refused by the guard. (spec: pm-mode)
- **The tracker is pushed**: after a commit in a companion clone; it succeeds, or fails and is said. (spec: pm-mode)
- **A sub-agent writes**: a write by a sub-agent of any session; the PM paths do not bear on it. (spec: pm-mode)
- **The owner runs /pap:pm start**: moves the tracker from absent to started, or reports from it. (spec: pm-mode)
- **The owner runs /pap:pm launch**: the owner types the command, which leaves a launch record; the launch logs a yes event and a launch event, commits the tracker and then starts one cycle from its brief, or is refused. (spec: pm-mode)
- **The PM session invokes /pap:pm launch itself**: a launch with no launch record; refused. (spec: pm-mode)
- **The PM session sends a cycle a message**: logged by the guard in the message log. (spec: pm-mode)
- **The tracker is committed**: moves the tracker from uncommitted to clean; in a companion clone it is then pushed. (spec: pm-mode)
- **A cycle opens its draft pull request**: the cycle's `/change` reaches its stop. (spec: pm-mode)
- **The owner runs /pap:plan**: in a main session, for one change; it starts a planner, resumes a plan draft, takes an edit to an accepted plan, or stops. (spec: plan-step)
- **A plan is drafted**: the planner returns a complete plan draft and the main session writes it; moves the plan from absent to a draft. (spec: plan-step)
- **A plan review runs**: the plan reviewer returns and the main session writes the plan review register; the plan draft is then reviewed. (spec: plan-step)
- **The owner says yes to the plan**: moves the plan from a draft to accepted; the plan and its register are committed on the change branch in one commit. (spec: plan-step)
- **A spec is changed after the plan's yes**: a commit to the spec later than the one that accepted the plan; moves the plan from accepted to a draft. (spec: plan-step)
- **/change is run**: by a cycle from its brief, or by the owner in a solo session; it builds the change. (spec: plan-step)
- **The owner runs /spec**: in a main session, for one change whose intent is accepted; it drafts the spec, starts a spec review where the class requires one, or resumes a draft. (spec: spec-board-keeps-tools)
- **A perspective reports**: its sub-agent returns a verdict and a findings table to the main session. (spec: spec-board-keeps-tools)
- **A spec review returns**: the last perspective reports; moves the spec review from running to returned. (spec: spec-board-keeps-tools)

## Rules

- Nothing is created, in the current directory or on GitHub, while a run is in preflight. (spec: pap-new)
- A run from an agent shell is refused before any sign-in is offered. (spec: pap-new)
- The first push comes before clone setup and before the repository settings are applied, so it meets no hook and no ruleset. If it meets a hook it stops; it never skips one. (spec: pap-new)
- A run never deletes a repository, never pushes to `main` twice and never makes a second first commit. (spec: pap-new)
- An agent token is requested only when the main ruleset exists with no bypass actor. (spec: pap-new)
- A welcome session starts only with a minted agent token, and never as the owner. (spec: pap-new)
- On a re-run the recorded version and layers, and the repository's own visibility and owner, stand; other values are refused. (spec: pap-new)
- A release is cut only when the install prompt names its version. (spec: pap-new)
- A session's mode is set by `pap claude` before Claude Code starts; nothing the session runs changes it while it runs. (spec: pm-mode)
- A session is never called PM without the guard: without the pap plugin it has no mode. (spec: pm-mode)
- A PM session writes nothing in any adopting repository but its own. (spec: pm-mode)
- `/pap:pm` runs in a main session, PM or solo, and never in a sub-agent. (spec: pm-mode)
- A PM session writes only the PM paths; any other write in an adopting repository, its own or another, is refused with the routes named, and so is a write to the guard's own files or to a path that cannot be resolved. (spec: pm-mode)
- Of the commands that write a commit, only `git commit` is judged against the PM paths. (spec: pm-mode)
- A sub-agent is never refused as outside the PM paths. (spec: pm-mode)
- Whatever the guard refused before pm-mode it refuses still, in every mode and for every sub-agent. (spec: pm-mode)
- No command a session runs sets or unsets its mode. (spec: pm-mode)
- A solo session starts only from the owner's own terminal, never from an agent shell. (spec: pm-mode)
- A cycle is launched only by the owner's typed command, from a complete brief, after a restate event for its slug, and never while in flight. The tracker is committed before the cycle starts. (spec: pm-mode)
- One PM session writes a tracker at a time. (spec: pm-mode)
- A PM session launches and resumes nothing on starting; it reports and waits for the owner. (spec: pm-mode)
- A welcome session is a PM session where the pap plugin is installed. (spec: pm-mode)
- A plan is drafted only from an accepted spec, and first accepted before code exists on the change branch; a yes after code exists is plan rework. (spec: plan-step)
- A plan is accepted only by the owner's yes, in a main session, with every finding of its plan review fixed or given a disposition. (spec: plan-step)
- The planner and the plan reviewer change no file; the main session writes the plan and the plan review register. (spec: plan-step)
- A build of a change that needs a plan is launched only when its plan is accepted; a launch that cannot read the change branch or the plan is refused. (spec: plan-step)
- A build reports its deviations; a deviation is never refused. A plan is data to a build: it never widens the tools, paths or scope its brief and spec give. (spec: plan-step)
- The sub-agents of a spec review change no file; the main session consolidates what they return and writes the spec review register. (spec: spec-board-keeps-tools)
- The spec review register is written in the turn the spec review returns, before the owner is asked for a disposition. (spec: spec-board-keeps-tools)
