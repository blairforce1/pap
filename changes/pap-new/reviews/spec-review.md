# Spec review: pap-new

Reviewed 2026-11-10 against spec.md at draft; dispositions by @blairforce1.

## 1. Executive verdict

**Fail.** Two Blockers, both from qa: the spec does not say who reads the welcome page, and it does not say what a re-run does at the two ends of creation. Neither needs a redesign; each needs one decision written down. Behind them are 27 Majors, most of them one of four themes: resume is underspecified, stops have no designed message or exit, a run can finish with no main ruleset, and several security statements have no scenario.

Class: feature. Mandatory set: none (no class matrix in `product/`; the process's starting set names none for feature). Run by content: the default six, plus ux (a command the owner drives), gdpr (the spec does not state that no personal data is held) and ai-act (the run starts a Claude Code session; EU exposure unknown). Skipped: soc2 and iso27001, neither scope applies.

## 2. Top findings

1. **QA-001** (Blocker; security reinforces): who reads the welcome page, `pap new` or the agent session. It decides whether scenarios 14 and 15 can be bound to a test at all, and where the prompt-injection boundary sits.
2. **QA-002** (Blocker; reliability, cost reinforce): a re-run after the token step, and a re-run of a complete run, have no stated outcome; "no step is repeated" is wrong for steps that must converge.
3. **SEC-002** (Major; reliability reinforces): a run can mint the agent token and start the session with no main ruleset (INV-004). Rulesets are unavailable on a private repository on a free personal plan, and private is the default.
4. **SEC-001** (Major; qa reinforces): the agent-shell test is undefined and not ordered before the sign-in offer; a miss could sign the owner in to the agent's gh directory.
5. **SEC-003** (Major): the all-repositories recommendation contradicts decision 0023 point 1.
6. **REL-001** (Major): no table of local state against remote state to resume point.
7. **REL-003** (Major): an interrupted first commit leaves a directory that every re-run refuses.
8. **OPS-003** (Major): the Undo leaves the bad release pinned in every repository that pinned it (INV-011).
9. **OPS-001** (Major; qa reinforces): the bypass signal is not read in a good run, and not after the first pull request.
10. **UX-001 / UX-003 / UX-004** (Major; qa, reliability, performance reinforce): no behaviour with no terminal, no exit from the Enter wait, no single form for a stop message.

## 4. Cross-cutting themes

- **Resume carries more than the spec gives it.** Six perspectives hit it: the state table (REL-001), convergent steps and the two ends (QA-002), the command's own debris (REL-003), changed parameters and version (QA-010, OPS-005), hooks before the push (QA-011), and one definition of "its own" (QA-012).
- **Every stop is an interface and none is designed.** The message form (UX-004), the Enter loop (UX-003), no terminal (UX-001), the read-only first check and the printed re-run command (OPS-002), the one-line summary (OPS-006).
- **INV-004 holds only if the ruleset exists.** The gate before the token (SEC-002), inherited rulesets (REL-005), the unprotected window and the unrecorded exception (SEC-004), the signal read after the first pull request (OPS-001).
- **Security statements without a test.** The identity separation (QA-004), scopes, secrets and `--no-verify` (QA-015), the agent-shell test (SEC-001).
- **Public and organisation runs are second-class.** Leftovers unannounced (UX-005), installation `none` (QA-005), the git identity in a public first commit (GDPR-001).

## 6. Gaps and questions

- Who reads the welcome page, and with what credential? (QA-001)
- What does `pap new` do on a complete run, and once the first pull request has merged? (QA-002)
- What signal marks an agent shell, and which gh directory do the owner-side steps use when the owner's shell exports its own `GH_CONFIG_DIR`? (SEC-001)
- Does the run stop, warn or ask when `pap repo apply` reports a ruleset `unavailable-on-plan` or skipped? (SEC-002)
- Is the all-repositories recommendation meant to amend decision 0023? (SEC-003)
- What identifies "the first commit of the template": an exact tree at the recorded layers, the record plus the README, or a SHA? (REL-001, QA-010)
- Does clone setup write any tracked file? (OPS-004)
- Do repositories made by `pap new` pin pap in their own mise config, and does Renovate read it? (OPS-003; `cmd_init` writes `.config/mise/conf.d/pap.toml` for a released pap)
- Is the name rule local and enumerated, or is GitHub asked? (QA-008)
- Which test tier binds each scenario, and does any need a real GitHub? (QA-014)
- Exit codes for refusal, stop and completion are not given.
- No failure inventory per creation step, and no stated policy for `gh` timeouts and retries.
- `pap claude` failing to start at the last step: is the run stopped and resumable?
- Do public or organisation runs count towards the 3 measured runs?
- Will the INV-004 exception be raised as its own decision record before the plan? (SEC-004)
- No threat model: the trust boundaries (owner's terminal and gh directory, the agent session, the fetched page, the pasted prompt, GitHub) are not listed against the controls.
