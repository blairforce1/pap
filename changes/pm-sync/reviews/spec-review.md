# Spec review: pm-sync

Reviewed 2026-11-12 against spec.md at draft; dispositions by @blairforce1.

Read by eight `pap:spec-reviewer` sub-agents, one a perspective, and
consolidated by the main session by the rules of `spec-review-full`.

## 1. Executive verdict

**Fail.** One Blocker: the rule that compares the asked version with the
recorded version and the pin has undefined cells, and the commonest state
(the pin bumped, the template not yet synced) falls in one. Every other
perspective passed or passed with conditions; the Majors below become
conditions.

Class: feature. Mandatory set: none (the repository has no class matrix;
the process's starting set names none for a feature). Selected by content:
the default six, ux (an operator types the command) and gdpr (the spec
does not state that no personal data is held). Skipped: ai-act (the design
is a shell script and calls no AI system), soc2 and iso27001 (no scope).

## 2. Top findings

1. **QA-001 (Blocker; UX-002, REL-002, OPS-001):** a version equal to the pin and newer than the record is neither allowed nor refused. It is the state INV-011 exists for.
2. **QA-002 (Major; UX-001, REL-003, OPS-002, SEC-006, QA-003):** the spoken ask has no mechanism. The skill is `disable-model-invocation: true`, so a PM session may never see its description; the session id is left to the plan; an invented id takes the tracker's lock for good.
3. **REL-001 (Major; OPS-003, QA-006):** a commit git refuses after the brief is written is not designed, and exit 18 is missing from the kept codes.
4. **SEC-001 (Major; QA-007):** the recorded version, the layers and the root go into the brief and the event log unvalidated, though the brief is a cycle's whole prompt. The Security section says otherwise.
5. **SEC-002 (Major; OPS-006):** the `sync: ` prefix can be typed by the PM session and the brief edited before launch, so the measure rests on a mark the measured party can forge.
6. **QA-004 (Major):** the template's text is not in the spec; the only oracle for the brief is the template itself.
7. **QA-005 (Major; PERF-002, COST-003, REL-005):** the order of the checks, and where the network read sits among them, is not given.
8. **QA-008 (Major; REL-009, OPS-005):** the "refused sync launches" signal cannot tell its cause, and a revert hangs on it.
9. **UX-003 (Major; COST-005, REL-011, SEC-007, OPS-009):** a session on an older plugin reads a doc that names a command it lacks and no longer holds the brief.

## 4. Cross-cutting themes

- **The local state is richer than the Background.** Pin and record differ, a record is unreadable, a slug is paused, a brief was edited: the spec designs the clean case.
- **The spoken path is asserted, not built.** Five perspectives found it has no mechanism.
- **Order and failure after the write.** What is checked first, what the network read blocks, and what a failed commit leaves.
- **The measure trusts what it measures.** The prefix, the `used` line and "the next audit" each need a reader or a check the spec does not name.
- **The doc and an older plugin.** Raised by six perspectives.

## 5. Trade-off register

- **Spoken ask against "no role change" (QA-002).** The PM session learns the form from the role text, which is under `plugins/pap/hooks/**`, a protected path the intent did not list; or the spoken ask is answered with the line to type, and the intent's desired outcome shrinks. The owner decides.
- **A fixed template against an expected-conflict sync (UX-004).** One text every time, or an owner's edit of one line before launch that the measure cannot see.
- **Refuse offline against write unverified (SEC-011, REL-012).** The spec refuses; the perspectives agree.

## 6. Gaps and questions

- What "a release" is: a tag, or a tag whose release can be installed.
- Whether the plugin a PM session loads follows the repository's pin.
- Who reads the three signals, and when, with `audit` unbuilt.
- No trust boundary statement: `.config/pap.toml`, the pin file, the tag list and `PAP_SOURCE` are all inputs to a cycle's prompt.
- A refused `sync` leaves no trace, so unasked attempts are invisible.
- Retention and data-subject rights for the tracker are inherited from pm-mode and not restated.
- Whether a paused or reported sync slug refuses a new `sync`.

## 7. Recommended conditions for approval

1. A decision table for the version against the record and the pin, with scenarios where they differ (QA-001).
2. The spoken path's mechanism: where the form, the script's path and the session id come from, and a refusal for an id with no live record (QA-002, QA-003).
3. Exit 18 and the restore on a failed commit; the push stated (REL-001).
4. A grammar and a refusal for every value filled into the brief and the event (SEC-001).
5. The measure made independent of the prefix, or the prefix declared a convention (SEC-002).
6. The template's text in the spec (QA-004).

8. The launch-refusal signal defined as it can be read; no revert on it alone (QA-008).
9. The doc names the first release with `sync` and what to do below it (UX-003).
