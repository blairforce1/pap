Reviewed 2026-11-13 against spec.md at draft; dispositions by @blairforce1.

Class feature. No task class matrix in `product/`, so no mandatory set; perspectives by content: the default six (security, reliability, operations, cost, performance, qa), ux (the command and the cycle report to an operator), gdpr (the spec does not state that it holds no personal data) and ai-act (the design runs an LLM cycle; EU exposure unknown). soc2 and iso27001 skipped: no SOC 2 scope, no ISMS. ## 2. Top findings

1. REL-001 (reliability, ux, operations, cost, performance, security): no defined way for the cycle to run a 6-minute command, and nothing undoes a run that is killed.
2. REL-002 (reliability, qa, operations): no behaviour for a failure after the pull request is open.
3. QA-003 (qa, security): the undo order is unspecified, and the pre-push hook refuses a delete push made from outside the change branch.
4. QA-001 (qa, ux, cost, operations, security, performance): the re-answer form has no syntax, exits or limits.
5. SEC-001 (security): hooks can be switched off through `GIT_CONFIG_*` in the environment, which the guard does not see.
6. QA-005 (qa, operations, security, ux, cost): skipping the cold review rests on #144's reading of 0024 point 5, written nowhere.
7. COST-001 (cost, qa, performance): the 30k target and the 49k to 86k baseline are measured differently.
8. QA-006 (qa): the cycle's behaviour on a red check, `risk:high`, or a risk still not read is unstated.
9. UX-003 (ux, security, qa): the route passed to the command is not checked against the version, and can carry new lines into the body.
10. REL-003 (reliability, operations): a bump overtaken by a change to `[Unreleased]` on main has no path.

## 4. Cross-cutting themes

- **The run's edges are undesigned.** Interrupts, timeouts, failures after the open, the undo order and concurrency each surfaced in three to six perspectives (REL-001, REL-002, QA-003, QA-010).
- **The command is the only check, so its inputs need checking.** The environment (SEC-001), the route (UX-003), the script copy (REL-007) and the invoking checkout (SEC-003) all reach a script the guard cannot see.
- **The measure is not like for like.** Tokens (COST-001) and time (PERF-003) are measured differently from their baselines or on a tier that cannot see them.
- **One unwritten reading carries the cold-review skip** (QA-005).

## 5. Trade-off register

- **Retries against a cheap undo** (REL-005 against REL-001's undo design): one retry saves an owner round trip on a blip; none keeps the command simpler and every failure visible.
- **Local checks against wall time** (COST-006, PERF-005): running check and test locally costs about 2 to 3 minutes and repeats CI, and buys failing before the push.
- **Close or keep a pull request after a late failure** (REL-002, OPS-003): closing leaves a closed agent pull request on the record; keeping it leaves an open one, exit 3.

## 6. Gaps and questions

- How the cycle runs the command and waits for CI, and what it does when its call times out.
- What a failure after the open does, and whether exit 2 then names a closed pull request.
- The re-answer form's syntax and exits.
- Whether the 49k to 86k baseline is a total or beyond the starting context.
- Which copy of the script runs.
- Whether a stale bump is closed and re-run or merged with main.
- The threat model: an agent that drifts (0027's scope), or one steered through a brief or route.
- EU exposure and licence (ai-act, Article 2(12)); whether the repository is public (gdpr). Project-wide, not this change's.
