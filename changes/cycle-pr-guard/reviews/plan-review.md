- PR-4 | design | Major | Two parsers read the command, and the plan wires the placement state into only one. Section Design adds `unplaced` to "the segment pass", the regex pass that splits on `&&`, `;` and `|` and tracks `cd` through its own `.dir`. The plan gives `pr` a "placed flag" but defines no `unplaced` state for `prbodies`, which also ignores `pushd`, `popd` and `cd -`. Scenarios 13 (rows 1, 2 and 4) and 14 therefore have no defined source for the flag on the gh side. | disposition: fixed: Design
- PR-5 | design | Major | The `sw` target comes from the segment pass, which splits on separators even inside quotes. A PM-session command such as `echo "done; git switch x"` or a commit message containing `; git checkout y` yields a segment that starts with `git switch ...`. The anchored capture then matches it, and the guard refuses it as a branch switch in the main checkout. The existing rules tolerate this because they only add refusals in the same cases. Rule 27.2 is a new false-refusal path, and the plan names no mitigation or test. Scenario 9 and the "False refusals" signal depend on this not happening. | disposition: fixed: Design, Tests
